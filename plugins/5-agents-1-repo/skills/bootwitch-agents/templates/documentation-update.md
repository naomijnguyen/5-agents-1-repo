# Documentation Ledger

The session overview agent maintains this file. Update project documentation only from evidence accepted by the architecture/integration lead.

## Touched Projects

| Project | Implementation owner | README | Architecture and diagrams | Technical notes | Evidence accepted | Lead review |
|---|---|---|---|---|---|---|

## Documentation Standards

### README

- What the project is and why it exists
- How to run or inspect it
- Current verified behavior
- Important limitations without unnecessary hedging
- Links to deeper architecture and technical material

### Architecture

- Current verified flow
- State owners, lifetimes, and boundaries
- Forward and backward traces where useful
- Dependencies and failure boundaries
- Diagrams that match the implementation
- Follow-up notes for valuable work outside the current scope

### Technical Notes

- Contracts and interfaces
- Runtime composition and dependencies
- Persistence, concurrency, and migration behavior
- Failure handling and recovery
- Verification commands and evidence

## Reconciliation Notes

Record documentation conflicts, stale claims removed, and terminology standardized during final review.
